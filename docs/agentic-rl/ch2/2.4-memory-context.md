# 2.4 记忆即动作：长程上下文与外部记忆强化学习

!!! abstract "本节摘要"
    窗口装不下时，通常做法是截断或摘要，但「留什么」是写死的规则。这一节的范式是把记忆操作本身变成动作：读一段、往记忆里写什么、删什么、查什么，都由策略决定并用 RL 训。再顺带分清它和 1.5 错题本的区别。

## 先分清两种「记忆」

| | 1.5 的 EMPO² 记忆 | 本节的记忆 |
| --- | --- | --- |
| 是什么 | 跨任务的经验总结（tips） | 单次任务内的信息载体 |
| 解决什么 | 新任务从零探索 | 单个任务太长，窗口装不下 |
| 类比 | 错题本 | 草稿纸 |
| 典型形态 | 自然语言条目存进库里检索 | 固定大小的记忆块被反复改写 |

本节讲右边这列：一本书有一百万字，窗口只有 8K，模型要学会边读边把要点抄到一张固定大小的纸上，读完凭这张纸答题。

## 把记忆操作变成动作

传统长文档处理是流水线：分块、摘要、拼接，规则固定。记忆即动作的做法把每一步都交给策略：

| 动作 | 例子 |
| --- | --- |
| 读 | 决定下一块读原文哪一段 |
| 写 | 把当前块的要点以什么形式写进记忆 |
| 改 | 发现新信息和旧记忆冲突时，更新或推翻旧条目 |
| 删 | 记忆满了，删哪一条 |
| 查 | 答题或决策前，从记忆里取什么出来 |

奖励还是终局的（答对、任务完成），但梯度落在这些记忆操作上。模型学到的不是某个领域的知识，而是「什么信息值得留」这个通用习惯。

**MemAgent**（[arXiv:2507.02259](https://arxiv.org/abs/2507.02259)）是代表：多轮分块阅读，每轮把固定长度的记忆改写一遍，用 RL 训这个改写策略，在百万级文本问答上外推。它证明了上下文长度可以靠「学会记笔记」而不是靠堆窗口。

**Memory-R1**（[arXiv:2508.19828](https://arxiv.org/abs/2508.19828)）把记忆的增删改查做成显式操作集合，用 RL 训一个记忆管理策略和一个答题策略的配合。后续的变体把操作组织成树或图结构，方便回溯和合并。

## 上下文管理：同一思想用在对话和 Agent 轨迹里

长程 Agent 里要管理的不是文档，而是自己的轨迹：30 步之前的工具返回还留不留、已完成子任务的细节能不能折叠。ContextPilot 一类工作把「折叠哪一段历史、保留哪一段原文」做成可训练决策，奖励是后续步的成功率和 token 成本。

这和推理模型里的上下文压缩、GUI 场景的历史截图压缩（2.3）是同一个问题的三个版本：**信息保留是一个决策，应该被优化，而不是被规则写死。**

## 难点

- **信用分配更绕。** 第 3 步删掉的那条记忆，到第 40 步才发现是关键证据。功劳要跨越几十步落到一个删除动作上，是 1.4 问题的时间拉长版。
- **记忆漂移。** 每轮改写都可能丢一点、错一点，几十轮后记忆和原文脱钩。需要周期性地回查原文校验，或在奖励里加记忆与原文的一致性核查。
- **评测难。** 记忆质量没有直接指标，只能看下游任务。消融时要固定下游，只换记忆策略，否则分不清是谁的功劳。

## 和直接扩窗口的关系

扩窗口（128K 到 1M）解决的是「装得下」，记忆管理解决的是「装得下也不该全装」：全塞进去，注意力被噪声稀释，成本按长度涨。两者会长期共存——窗口越大，需要主动管理的阈值越高，但不会消失。

# 2.1 搜索与深度调研智能体

!!! abstract "本节摘要"
    搜索是最先被 RL 训起来的 Agent 场景，因为它有一个难得的组合：动作简单（发查询、读文档、给答案），终局又能判对错。本节按状态、动作、验证器拆开这个场景，再看 Search-R1、ZeroSearch 到真实网页 Deep Research 的演进。

## 这个场景长什么样

| 要素 | 内容 |
| --- | --- |
| 状态 | 用户问题 + 已检索到的文档集合 + 已确认的事实 |
| 动作 | 生成查询词、决定读哪篇、决定何时停下来作答 |
| 观测 | 搜索引擎返回的标题、摘要、正文片段，有噪声、会重复、可能互相矛盾 |
| 奖励 | 最终答案对错为主；查询次数、引用是否属实是常见的辅助项 |
| 难点 | 什么时候该再搜一次而不是直接答；搜到的错误信息会污染后面所有步 |

和数学题比，搜索多了一个决策：**信息够不够**。搜太少会编，搜太多浪费且容易被噪声带偏。这个「何时停」本身就是要学的策略。

## Search-R1：把掩码和多跳一起立起来

Search-R1（[arXiv:2503.09516](https://arxiv.org/abs/2503.09516)，UIUC）是这条线的奠基工作，贡献有两件，都在第 1 章出现过：

1. **检索词元掩码**：搜索引擎返回的文档只进上下文，不算损失（1.1 的掩码表就是它的场景）。
2. **多跳在训练里涌现**：只给终局答案奖励，模型自己学会改写查询、第二跳验证第一跳的结果，而不是一次检索就作答。

同期的 R1-Searcher、ReSearch 走的是同一路：终局可验证 + 掩码 + 组相对更新。它们的共同结论是，在搜索任务上 RL 明显优于只做 SFT 模仿检索轨迹，因为「何时搜、搜什么」需要试错，而不是背固定流程。

## ZeroSearch 与 SSRL：不打真实搜索 API 也能练

真实搜索 API 贵、慢、结果还会随时间变，训练不可复现。ZeroSearch（[arXiv:2505.04588](https://arxiv.org/abs/2505.04588)）先轻量训一个模型扮演搜索引擎，按要求返回有用或干扰文档，再用它当环境训搜索策略，并逐步把文档质量调差做课程。SSRL（[arXiv:2508.10874](https://arxiv.org/abs/2508.10874)）更进一步，用模型内部知识模拟检索交互。

边界要说清：省的是外部调用和不可复现性，不是零成本；模拟器给不出训练之后的新事实，策略在模拟环境里学到的查询习惯，迁到真实搜索引擎时要重新校准。工业界的共识是模拟练基本功、真实环境做后期对齐，两段都要。

## Deep Research：从答一道题到写一份报告

Deep Research 把终局从「一个答案」变成「一份带引用的报告」，奖励立刻变难：

- 答案对错只能判其中的事实点，报告结构、覆盖面、引用是否真的支持结论，都没有唯一真值。
- 轨迹变长到几十次检索，信用分配回到 1.4 的问题：哪一次检索真正提供了关键证据。
- 网页是开放环境：页面会变、会有 SEO 垃圾和互相矛盾的来源，「搜到了」不等于「可信」。

代表做法包括 DeepResearcher（在真实网页环境里做 RL）、GLM-5 的搜索数据合成（从真实浏览网页建知识图谱，再出多跳题并过滤掉不用搜就能答的题，详见后训练报告 2.10），以及用证据链做步级信号的一类工作（和 IGPO 的思路相通：这一步检索让关键证据的把握涨了多少）。

评测上常用 GAIA、BrowseComp 这类需要真实检索的基准。它们的共同特点是答案可核查、过程不限制，正适合 RL；但网页漂移使分数复现性天然弱于数学基准，比较时要看评测时间和方法细节。

## 这个场景最容易踩的坑

- **引用幻觉**：结论对了，但引用的文档根本没说这句话。只判终局答案会把这种轨迹一起奖了，需要单独的引用核查项（CM2 式清单在这里很合适）。
- **检索依赖症**：什么都搜，简单问题也搜三轮。要在奖励里计查询成本，或用难度课程让模型学会先用内部知识。
- **被第一条结果锚定**：只读排名第一的文档。训练数据里要有来源冲突的情形，逼模型交叉验证。

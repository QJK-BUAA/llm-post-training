# 3.2 规模化环境合成与 Agent 专属防作弊

!!! abstract "本节摘要"
    Agent 训练的上限由环境决定：有多少个逻辑自洽、能自动判分、没有作弊漏洞的沙箱，就能训多复杂的技能。本节讲四种批量造环境的范式，再列一份 Agent 时代特有的作弊图谱——这些作弊在单轮数学题里不存在，在能改文件、能跑命令的环境里全存在。

## 为什么环境是瓶颈

单轮数学题可以直接用现成题库。多轮任务要的是能交互的世界：一个能跑测试的代码仓库、一台能装软件的虚拟机、一个有状态的模拟商店。人工造一个要数小时，训练要上万个。所以 2025 年之后，竞争从「谁的算法好」变成「谁造环境又快又严」。

## 四种合成范式

| 范式 | 怎么做 | 代表 | 产出 |
| --- | --- | --- | --- |
| 真实仓库逆向注错 | 找测试全绿的真实仓库，自动注入缺陷，让部分测试变红 | SWE-smith（[2504.21798](https://arxiv.org/abs/2504.21798)） | 5 万+ 带真实 Docker 验收的修复任务 |
| 代码生成整个后端 | 从场景描述生成数据库、状态逻辑和接口 | Agent World Model（[2602.10090](https://arxiv.org/abs/2602.10090)） | 1000+ 可执行环境 |
| 工具拓扑合成任务 | 在 MCP 工具图上规划多步依赖，合成任务和轨迹 | ASTRA（[2601.21558](https://arxiv.org/abs/2601.21558)） | 可验证的工具交互数据 |
| 文档转环境 | 从非结构化文档抽出工具和验证逻辑 | GEM（[2601.10355](https://arxiv.org/abs/2601.10355)）、ABE（[2508.08791](https://arxiv.org/abs/2508.08791)） | 任务环境和轨迹 |

四种范式都要过同一道质检：**环境本身是否稳定**。同一个任务、同一个正确解，跑十次应该十次通过；验收脚本时好时坏（flaky），奖励就成了噪声，RL 会先学会迎合这种噪声。入库前用参考解和空操作各跑一遍——参考解必须过、空操作必须不过——是最便宜的双向校验。

合成环境还有分布偏差：模拟器的文档、工具返回格式、错误信息都比真实世界干净。在模拟里训满分、到真实 API 就掉，是常见现象。对策是混合真实环境做后期训练，或在模拟器里主动注入失败和噪声（Kimi K2 的工具模拟器就带可控异常，见后训练报告 2.2）。

## Agent 专属作弊图谱

单轮时代的作弊是「讨好打分模型」。Agent 能动手改环境，作弊直接升级成破坏验收本身：

| 作弊手法 | 具体做法 | 防御 |
| --- | --- | --- |
| 改测试骗绿 | 把断言改松、删掉失败用例、改测试文件 | 测试目录只读挂载；验收在训练沙箱外执行；测试文件哈希校验 |
| 偷看未来 | `git log`、`git show` 看到真实修复提交，或读到参考解 | 清洗 git 历史和元数据；参考解放在 Agent 读不到的路径 |
| 改评测脚本 | 改验收脚本让它恒返回成功、改退出码 | 验收脚本与环境隔离；退出码加结果文件双通道校验 |
| 硬编码过测 | 针对可见测试用例写特判 | 隐藏测试集；随机化测试输入；留出测试不进训练环境 |
| 刷过程分 | Rubric 按工具调用次数或格式给分时，堆无意义调用 | 过程奖励只认有效状态变化；调用计成本（1.1 的奖励设计） |
| 假装完成 | GUI 里做出「看起来完成」的界面，后端实际没生效 | 验收查后端状态，不查截图观感（2.3） |
| 环境探测 | 试探评测边界、读取环境变量里的答案 | 最小权限；敏感信息不进环境；异常行为日志审计 |

规律是：**验收和被训对象必须隔离**。Agent 能写到的地方，验收逻辑就不能放在那里；Agent 能读到的地方，答案就不能放在那里。这和考试不能让学生保管标准答案是同一个道理，但工程上极易疏忽，因为图省事把验收脚本顺手放在同一个容器里。

## 防作弊清单（造环境时逐项过）

1. 测试与验收脚本只读，或在沙箱外执行。
2. git 历史、参考解、隐藏测试不进入 Agent 的文件系统。
3. 参考解通过、空操作失败、随机乱做失败，三种基线都验过。
4. 同一任务重复跑 10 次，验收结果一致（不 flaky）。
5. 奖励里计入调用和步数成本，防止刷过程分。
6. 过程奖励认状态变化，不认动作次数。
7. 保留异常轨迹日志，定期人工抽查模型是不是在用你没想到的方式过关。

# 1.9 GSPO — 序列级策略优化

!!! abstract "本节摘要"
    GSPO（Group Sequence Policy Optimization）指出了 GRPO 在长序列与混合专家（MoE）架构下的结构性错配：奖励是整条序列给一个标量，重要性采样比率却逐 token 独立计算并裁剪。通过改用长度归一化的**序列级几何平均重要性比率**，GSPO 平滑了 MoE 专家路由切换引入的逐 token 概率跳变噪声，无需依赖繁重的 Routing Replay 即可实现大规模 MoE RL 稳定训练，并应用于 Qwen3 系列。

!!! abstract "论文：GSPO"
    *Group Sequence Policy Optimization* (Alibaba / Qwen Team, 2025)  
    **arXiv**: [2507.18071](https://arxiv.org/abs/2507.18071)  
    **历史地位**: 将策略优化的重要性采样与裁剪粒度从 Token-Level 提升至 Sequence-Level 的代表算法。

## 核心问题：粒度错配与 MoE 路由失稳

在结果奖励（Outcome Reward）场景下，GRPO 存在一个长期被忽视的**理论与架构双重缺陷**：

1. **优化粒度错配**：奖励信号 $\hat{A}_i$ 是对**整条序列 $y_i$** 打分的，但重要性采样比率 $r_{i,t}(\theta)$ 却是按**单个 token** 计算的；单步采样根本没有为每个局部前缀提供多条独立校正样本。
2. **MoE 模型的灾难性放大**：在稠密（Dense）模型上，单步参数更新前后同一个 token 的概率变化通常很平滑；但在 **MoE（Mixture-of-Experts，混合专家）** 模型上，微小参数更新就会触发门控网络（Router）切换激活的专家子集，导致个别 token 的 $r_{i,t}(\theta)$ 出现剧烈噪声跳变，训练极易在几百步后彻底崩溃。

## 核心公式

对问题 $x$ 采样的 $G$ 条回答 $\{y_1, \ldots, y_G\}$，**GSPO 目标函数**在序列级别进行裁剪与优化：

$$
\mathcal{J}_{\text{GSPO}}(\theta) = \mathbb{E}_{x \sim \mathcal{D},\, \{y_i\}_{i=1}^G \sim \pi_{\theta_{\text{old}}}(\cdot\mid x)} \left[ \frac{1}{G} \sum_{i=1}^{G} \min\!\Big( s_i(\theta)\, \hat{A}_i,\; \mathrm{clip}\!\big(s_i(\theta),\, 1-\varepsilon_{\text{left}},\, 1+\varepsilon_{\text{right}}\big) \hat{A}_i \Big) \right]
$$

其中 **长度归一化的序列级重要性比率 $s_i(\theta)$** 定义为逐 token 重要性比率的**几何平均**（等价于对数概率比的长度算术平均再取指数，注意分母是采样用的旧策略 $\pi_{\theta_{\text{old}}}$）：

$$
s_i(\theta) = \left(\frac{\pi_\theta(y_i \mid x)}{\pi_{\theta_{\text{old}}}(y_i \mid x)}\right)^{\frac{1}{|y_i|}} = \exp\!\left(\frac{1}{|y_i|} \sum_{t=1}^{|y_i|} \log \frac{\pi_\theta(y_{i,t} \mid x, y_{i,<t})}{\pi_{\theta_{\text{old}}}(y_{i,t} \mid x, y_{i,<t})}\right)
$$

??? info "📖 初学者补充：为什么不能直接用整条序列的原始概率比 $\frac{\pi_\theta(y_i\mid x)}{\pi_{\theta_{\text{old}}}(y_i\mid x)}$，而必须开 $|y_i|$ 次方？"
    整条序列的概率等于所有 token 条件概率的连乘：$\frac{\pi_\theta(y_i\mid x)}{\pi_{\theta_{\text{old}}}(y_i\mid x)} = \prod_{t=1}^{|y_i|} r_{i,t}(\theta)$。
    假设序列长度 $|y_i| = 4,000$，哪怕每个 token 的概率仅仅一致微增了 $1\%$（$r_{i,t} = 1.01$），连乘 $4,000$ 次之后整句概率比就会变成 $1.01^{4000} \approx 1.9 \times 10^{17}$（直接浮点数上溢爆炸）；反之若微降 $1\%$，连乘后就变成 $0.99^{4000} \approx 3.3 \times 10^{-18} \approx 0$！而且不同回答长度不同，连乘值的数值尺度根本不可比。

    取 $\frac{1}{|y_i|}$ 次幂（几何平均）后，$s_i(\theta)$ 被拉回到与序列长度无关的稳定尺度（上例中恒为 $1.01$）。并且对未裁剪分支求导时：

    $$
    \nabla_\theta s_i(\theta) = s_i(\theta) \cdot \frac{1}{|y_i|} \sum_{t=1}^{|y_i|} \nabla_\theta \log \pi_\theta(y_{i,t} \mid x, y_{i,<t})
    $$

    这意味着**同一条序列内的所有 token 共享同一个干净的序列级标量权重 $s_i(\theta)$**，不再受个别 token 局部比率抖动的干扰。（注：论文还给出了支持传入逐 token 优势的变体 GSPO-token，核心仍是用序列比率抑制局部方差。）

### 极紧凑的裁剪阈值

正因为 $s_i(\theta)$ 对整条序列做了平均平滑，它的正常波动幅度比单个 token 的 $r_{i,t}$ 紧凑得多。论文中 GSPO 的裁剪范围取在 $10^{-4}$ 量级：

$$
\varepsilon_{\text{left}} = 3 \times 10^{-4}, \qquad \varepsilon_{\text{right}} = 4 \times 10^{-4}
$$

与 GRPO / DAPO 的 $\varepsilon \in [0.2, 0.28]$ 相比，数值尺度相差约三个数量级——这不是说 GSPO 不让模型更新，而是序列几何均值偏离 $1$ 达 $4\times 10^{-4}$ 时，累积到几千个 token 上已经对应着相当可观的整句分布移动。

## 深入剖析：为什么 MoE 模型的 RL 训练这么容易崩？

!!! warning "MoE + Token-Level RL 的三重放大失稳机制"
    MoE 架构在 RL 中叠加了稠密模型不存在的离散跳变。以下三点是 GSPO 论文以及 AReaL、ROLL、veRL、Megatron-LM 等开源社区反复验证的根因：

### ① 专家路由翻转（Routing Volatility）

MoE 的每一层都通过门控网络（Gating Network）从数十～数百个专家中离散挑选 `top-k` 个专家（例如 Qwen3-MoE 每层 128 选 8，激活率不足 10%）。当策略参数经历哪怕一两步微小的梯度更新（甚至仅仅因为推理引擎 vLLM 与训练引擎 Megatron 的算子浮点舍入顺序不同），排在第 $k$ 名与第 $k+1$ 名的专家得分就可能发生微弱逆转，导致离散 `argtopk` 选择换人：

$$
\underbrace{\mathrm{argtopk}\big(\mathrm{Gate}_{\theta_{\text{old}}}(h_t)\big)}_{\text{Rollout 采样时激活的专家子网}} \;\neq\; \underbrace{\mathrm{argtopk}\big(\mathrm{Gate}_{\theta}(h_t)\big)}_{\text{训练前向时激活的专家子网}}
$$

### ② Token-Level IS Ratio 被路由跳变噪声淹没

一旦某几层的激活专家换了，同一个 token 在 $\pi_\theta$ 与 $\pi_{\theta_{\text{old}}}$ 下相当于走过了**不同的物理子网络**。此时逐 token 比率 $r_{i,t}(\theta) = \frac{\pi_\theta(y_{i,t}\mid \cdots)}{\pi_{\theta_{\text{old}}}(y_{i,t}\mid \cdots)}$ 的剧烈跳变中，很大一部分是**离散路由切换与跨引擎数值噪声**，而非策略意图的真实偏移。

### ③ Token 级硬裁剪在噪声场中诱发不可逆崩溃

当成千上万个含有高方差路由噪声的 $r_{i,t}$ 逐个撞上 $[1-\varepsilon, 1+\varepsilon]$ 硬边界时，裁剪机制不再起到健康的信任域保护作用，而是有偏地过滤掉大量本应更新的 token、放过噪声方向；误差沿几千 token 的长思维链不断累积，最终引发奖励断崖式下跌与不可逆崩溃。

!!! quote "GSPO 论文核心诊断（§3）"
    *"The instability of GRPO stems from the fundamental misapplication and invalidation of importance sampling weights ... high-variance training noise that progressively accumulates with increased response length and is further amplified by the clipping mechanism."*

## 对照：工程侧的路由锁死方案 —— Routing Replay（R2 vs R3）

在改变算法粒度之外，工业界（如 DeepSeek-V3.2 的 Keep Routing、Megatron-LM、veRL、ms-swift 及论文 [arXiv:2510.11370](https://arxiv.org/abs/2510.11370)）发展出的另一条工程路径是 **Routing Replay（路由重放）**：记录采样时选中的专家下标，在训练前向时强行覆盖门控选择。根据**录制路由的位置不同**，又演化出 **R2** 与 **R3** 两代：

```text
                        R2 录制点 ↓               R3 录制点 ↓
                                  │                         │
RL 时间轴 →  ① Rollout (vLLM/SGLang)   ② Recompute (Megatron)   ③ Update (Megatron)
                    │                           │                        │
               实际采样生成回答             训练引擎重算 old_logp     多步 forward + backward
                 [ 路由 A ]                  [ 路由 B ]               [ 路由 C ]

             • R2 (Recompute Replay): 录制 B → 强制阶段 ③ 重放 B  （阶段 ①↔② 的跨引擎偏差仍在）
             • R3 (Rollout Replay)  : 录制 A → 强制阶段 ②、③ 全程重放 A （全链路物理路径彻底锁定）
```

| 对比维度 | **R2（Recompute Replay）** | **R3（Rollout Replay）** |
|----------|---------------------------|--------------------------|
| **路由录制位置** | 阶段 ②（训练引擎内部第一次前向） | 阶段 ①（推理引擎实际生成 token 时） |
| **消除的不一致** | 仅消除训练阶段多步 mini-batch 更新间的路由漂移 | **同时消除跨引擎（推理 vs 训练）与多步更新间的路由漂移** |
| **是否需侵入推理引擎** | 不需要 | 需要（如改造 vLLM/SGLang 返回每层 `routed_experts`） |
| **工程与通信负担** | 中等（跨专家并行 EP 缓存索引，门控局部梯度受限） | 较高（需跨训推进程传输全序列路由张量） |

!!! info "实测参考：Qwen3-30B-A3B + GRPO"
    在 Megatron-LM 社区针对 Qwen3-30B-A3B（MoE）的实测对比中：不开启路由重放得分为 **62.23**，开启 **R3 Rollout Replay** 后提升至 **71.83**，训推 KL 散度降低约一半并彻底消除了中途崩溃。

## GSPO 稳定 MoE 训练的四重机理与工程红利

1. **对数平均平滑局部路由抖动**：取对数后 $\log s_i(\theta) = \frac{1}{|y_i|}\sum_{t=1}^{|y_i|} \log r_{i,t}(\theta)$。只要单个 token 上由专家切换带来的对数概率扰动近似零均值、弱相关，对整条序列取平均就会将局部尖峰大幅摊平（在近似独立假设下标准差按 $O(1/\sqrt{|y_i|})$ 收缩），长序列反而比短序列更平稳；
2. **重要性比率粒度与序列奖励对齐**：一条序列一个奖励 $\hat{A}_i$，配一条序列一个整体偏移比率 $s_i(\theta)$，同一序列内所有 token 同向同比例更新；
3. **裁剪重新回到整句信任域角色**：不再因个别 token 的路由跳变误删局部梯度，而是衡量整条回答的总体似然偏离是否超标；
4. **大幅减轻基础设施耦合**：即便不侵入改造推理后端做 Routing Replay，单靠算法层的序列平均就能吸收大部分 vLLM 与训练后端间的混合精度及路由细微差异（在 TRL $\ge 0.20$ 中仅需配置 `importance_sampling_level="sequence"`；若在极端异步场景下与 R3 叠用，同样兼容）。

## GRPO vs GSPO（面向 MoE 场景）一表总结

| 维度 | GRPO（Token-Level IS） | GSPO（Sequence-Level IS） |
|------|------------------------|---------------------------|
| **重要性比率定义** | 每 token 独立 $r_{i,t}(\theta)$ | 整序列几何均值 $s_i(\theta)$ |
| **裁剪阈值量级** | $\varepsilon \approx 0.2$ | $\varepsilon \approx 3\times 10^{-4} \sim 4\times 10^{-4}$ |
| **MoE 路由跳变影响** | 逐 token 噪声直接冲击裁剪边界，极易崩溃 | 经全序列对数平均大幅平滑，原生稳定 |
| **对 Routing Replay 的依赖** | 在大规模 MoE 上几乎必需（如 Keep Routing / R3） | 无需依赖即可稳定收敛（亦可与 R3 互补叠用） |
| **适用架构收益** | Dense 模型表现良好，MoE 脆弱 | Dense 提升温和，**MoE 稳定性与性能质变** |

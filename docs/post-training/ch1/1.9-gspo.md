# 1.9 GSPO

论文：*Group Sequence Policy Optimization*（Qwen Team，[arXiv:2507.18071](https://arxiv.org/abs/2507.18071)）。官方说明：[Qwen 博客](https://qwenlm.github.io/blog/gspo/)。

GRPO 的奖励是整条回答一个分数，重要性比率却是每个 token 一个。优化单元和奖励单元不在同一层。MoE 上，这个 token 比率还会被路由波动放大。GSPO 把比率改成整段回答的几何平均，裁剪也发生在这一层。

## 序列比率

$$
\mathcal{J}_{\mathrm{GSPO}}(\theta)
= \mathbb{E}
\left[
\frac{1}{G}
\sum_{i=1}^{G}
\min \Big(
s_i(\theta)\, \hat A_i,\;
\mathrm{clip}(s_i(\theta), 1-\varepsilon, 1+\varepsilon)\, \hat A_i
\Big)
\right]
$$

$$
s_i(\theta)
= \left(
\frac{\pi_\theta(y_i \mid q)}{\pi_{\theta_{\mathrm{old}}}(y_i \mid q)}
\right)^{1/|y_i|}
= \exp \left(
\frac{1}{|y_i|}
\sum_{t=1}^{|y_i|}
\log
\frac{\pi_\theta(y_{i,t} \mid q, y_{i,<t})}{\pi_{\theta_{\mathrm{old}}}(y_{i,t} \mid q, y_{i,<t})}
\right)
$$

分母是**采样时的旧策略**，不是 KL 用的参考模型。\(s_i\) 是 token 比率的几何平均。同一条回答里的 token 共用这一个 \(s_i\)。

因为已经用长度做了指数平均，\(s_i\) 离 1 很近。论文使用的裁剪宽度约在 \(10^{-4}\)：左侧 \(3\times 10^{-4}\)，右侧 \(4\times 10^{-4}\)。GRPO 的 \(\varepsilon\) 在 0.2 附近，两者相差三个数量级。

## MoE 上 token 比率为什么抖

MoE 每一层用门控选出 top-k 个专家，Qwen3 一类模型的激活比例大约是总专家的 10%。参数更新一点点，top-k 的离散选择就可能换人。于是同一条回答在旧参数和新参数下，前向经过的专家集合不同。

token 比率 \(\pi_\theta / \pi_{\theta_{\mathrm{old}}}\) 仍然是两个模型输出概率的比，数学上可以定义。问题出在数值：比值里很大一部分来自路由跳变，而不是这条 token 的策略真的变了这么多。长序列上，每个 token 的噪声再被裁剪单独处理，clip 截住的常常是路由噪声。论文把训练不稳描述为：重要性权重被用在了和奖励不匹配的粒度上，方差随回答变长而积累，裁剪再把这种噪声放大。

几何平均把 token 对数比率做算术平均。若把每个 token 的路由噪声看成近似零均值，平均后的波动会随长度下降。这个 \(O(1/\sqrt{|y|})\) 只在噪声近似独立时成立。同一条序列共享参数，token 之间并不独立，所以它是一个有用的量级估计，不是定理。长度变长对序列比率更有利，对 token 比率更不利，这个方向是站得住的。

稠密模型没有这层离散路由，GSPO 相对 GRPO 的增益小。MoE 上它是稳定性的主要来源之一，Qwen3 的指令、代码和思考模型都用了它。

## Routing Replay 仍然有用

在 GSPO 之前，常见工程办法是记下采样时每个 token 选了哪些专家，训练前向强制走同一组专家。这样新旧概率至少经过同一套子网络。

代价是：专家并行要传递路由下标；门控自己的梯度被部分冻住；vLLM 和训练引擎的路由必须一致。它压住的是「两次前向走了不同专家」，没有改变 token 级比率和序列奖励错配这件事。

录制点还有两代：

| | R2 | R3 |
| --- | --- | --- |
| 录在哪 | 训练引擎重算旧对数概率时 | 推理引擎真正采样时 |
| 对齐的是 | 训练引擎内部两次前向 | 推理引擎和训练引擎之间 |
| 是否改推理后端 | 不需要 | 需要推理引擎返回专家下标 |

Megatron-LM 的一次 Qwen3-30B-A3B 加 GRPO 对照里，无 replay 为 62.23，R3 为 71.83。R3 多出来的部分来自采样路径和重算路径的差异。

GSPO 把路由噪声在序列比率里摊薄，R3 把三条前向的路由锁成同一份。二者可以叠用。序列比率没有从定义上废掉路由重放。

## 和「每个 token 一个权重」的关系

DAPO、CISPO 把损失分到 token，是为了让长回答里的 token 不被长度平均稀释，或让越界 token 仍有梯度。GSPO 把重要性比率升到序列，是因为奖励本来就是序列级的。只有奖励也细到 token 或步骤时，token 级比率才和信号同粒度。

    2.5 多智能体协同与角色演化¶

    本节摘要

    单个 Agent 包打天下会遇到上下文、延迟和专长三个瓶颈。多智能体把任务拆给多个角色，代价是训练更难：大家一起变，环境就不稳定；赢了不知道是谁的功劳。本节讲三种训练形态：只训编排器、联合训练、自博弈。

    为什么要拆¶

    瓶颈 拆开怎么缓解
    上下文 每个子 Agent 只看自己那块，结论回传
    延迟 独立子任务并行跑
    专长 搜索、写代码、审校可以是不同策略或不同提示
    互相检查 一个生成、一个挑错，比自检更不容易放水

    代价也明确：多了一个协调问题，和一个更难的信用分配问题。

    形态一：只训编排器，子智能体冻结¶

    Kimi K2.5 的 PARL 是代表（细节在后训练报告 2.2）：一个可训练的编排器负责拆任务、派子 Agent、汇总；子 Agent 是冻结的策略快照，输出当环境观测看待。

    这样设计是因为联合训练有个死结：最终奖励是团队的，落不到每个角色头上；而且每个角色都在变，其他角色面对的「环境」就一直在漂。冻结子 Agent 后，编排器面对的是稳定环境，问题退化成普通的单 Agent RL，只是动作变成了「派谁去做什么」。

    奖励要防两种作弊：退化成单 Agent 串行干完（不拆），和拆出一堆空壳子任务刷并行分（乱拆）。PARL 用并行奖励和完成奖励管这两头，训练后期把这两项退火到零，只留任务成败。

    形态二：联合训练——先解决尺度对不齐¶

    真要一起训，第一道坎是优势归一化的尺度。搜索 Agent 的奖励在 0/1，审校 Agent 的奖励是连续分，直接混在一个组里算均值方差，量级大的会把量级小的梯度吞掉。

    Dr. MAS（arXiv:2602.08847）的做法是按角色各自归一化：每个 Agent 用自己的奖励统计算自己的优势，再更新。它解决的是尺度干扰，不解决协作冲突本身——角色目标互相矛盾时（一个想快、一个想稳），归一化救不了，需要在奖励设计里把分工写清。

    MAPoRL、MARFT 一类工作探索多 Agent 的联合策略优化和角色分工形成。共同的经验是：先让单个角色能独立工作，再联合微调；一上来就联合训，大概率互相拖死。

    形态三：自博弈——对手或出题人也是模型¶

    • 出题—解题：一个模型出题、一个模型解题，难度自动跟上（和后训练报告 2.9 的 LSP 同源）。用在 Agent 上，出题人造的是带环境的多步任务。
    • 红蓝对抗：攻击方造刁钻输入或找漏洞，防守方修。适合安全和鲁棒性训练。
    • 生成—评判：一个写、一个挑错，评判信号当奖励。这和单 Agent 的自评区别在于评判者独立训练，不容易和生成者串通放水——但两个模型共谋退化（一起学会应付了事）仍是已知风险，要靠外部可验证信号定期锚定。

    这一块最难的三件事¶

    1. 团队奖励落不到个人。 解法谱系和单 Agent 的信用分配同构：按角色归一化、按贡献做反事实基线（换掉某个角色重跑，看结果差多少，贵但准）、或干脆冻结大部分角色只训一个。
    2. 非平稳性。 每个角色都是其他角色的环境。冻结、轮流更新、参数共享加角色条件，是常见的三种稳定化。
    3. 评测归因。 团队分数涨了，是编排变好了还是某个子 Agent 变强了？消融要能单独替换每个角色，否则论文数字很难解读。

    多智能体目前仍是五大场景里最不成熟的一块：形态一已经在产品里跑，形态二三大多在受控环境里验证。判断一个多 Agent 工作时，先问它属于哪种形态、冻结了谁，比看总分更有用。

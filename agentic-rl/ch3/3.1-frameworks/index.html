    3.1 开源 Agentic RL 训练框架架构对比¶

    本节摘要

    框架选错，后面每个实验都要和基础设施搏斗。本节按两种抽象流派拆开源框架：以分布式计算编排为核心的 veRL 系，和以环境交互为核心的 SkyRL、AReaL 系，最后给一张按场景选型的对照表。

    先看一个多轮训练系统必须有的五件东西¶

    1. 生成器：跑策略采样，多轮时要能中间停下来等环境。
    2. 环境层：成百上千个沙箱、浏览器或模拟器，要能并发、复位、超时回收。
    3. 轨迹管理：拼上下文、打掩码、记每步的旧对数概率和版本。
    4. 训练器：算优势、做更新，处理异步带来的旧数据。
    5. 调度：谁先跑、谁等待、权重多久同步一次。

    框架的差别，本质是这五件東西的抽象边界划在哪里、哪些是可替换的。

    流派一：分布式计算编排内核——veRL 系¶

    veRL（火山引擎）从单轮 RLHF 出身，抽象是 Controller、WorkerGroup、ResourcePool、DataProto：核心关心的是策略、Critic、参考模型、奖励模型这些大模型怎么在 GPU 集群上放置和调度，吞吐拉满。

    它的多轮扩展沿两条路：

    • verl-agent：在 veRL 上加步级环境交互，支持长程多轮和可定制的记忆与逐步输入，算法侧覆盖 PPO、GRPO、DAPO、REINFORCE++ 等。
    • VerlTool：把工具调用做成统一服务端 API，工具即环境，每个工具一个文件就能接进来，轨迹的环境状态可存可恢复，actor 采样和环境交互解耦。

    适合：已有 veRL 经验、要训大模型、吞吐和模型并行是主要矛盾的团队。代价是环境语义不是它的一等公民，复杂多轮逻辑要自己在它的抽象上搭。

    同派的 OpenRLHF（Ray + vLLM + DeepSpeed）更偏 RLHF 全家桶，多轮支持在跟进。

    流派二：环境原生的全栈——SkyRL、AReaL、RAGEN¶

    SkyRL 把系统拆成 Trainer、Generator、Inference Engine、Environment、Controller，环境以 Gym 风格接口为中心，生成器负责产完整轨迹并算奖励。各件可独立替换，可共置也可分离部署，支持同步和异步流水线。它还有配套的环境库（SkyRL-Gym）。适合从零搭多轮、环境种类多、要快速换环境做实验的团队。

    AReaL（蚂蚁与清华等）主打全异步：生成和训练彻底解耦、流式产轨迹，用陈旧度控制管旧数据，是大规模异步 Agent 训练的代表实现。后续的系统工作进一步把轨迹数据协议、数据治理和何时更新权重的控制面标准化，面向企业级自演进 Agent 负载。适合轨迹长尾极端、同步等待代价不可接受的场景。

    RAGEN 是研究向的轻量闭环：和 StarPO 算法配套（见 1.2），内置多个受控环境和训练动力学诊断（奖励方差、梯度尖峰、回声陷阱检测）。它不追求千卡吞吐，追求的是能看清训练为什么崩。适合研究和教学，先在小环境把算法调明白再上大框架。

    Agent Lightning 走另一条路：不重写你的 Agent，而是给现有 Agent 框架（不管用什么写的）加一个 RL 训练层，把执行轨迹转成训练信号。适合 Agent 产品已经成型、只想给其中某几个决策点加 RL 的团队。

    选型对照¶

    你的处境 优先看 理由
    大模型、已有 veRL、吞吐优先 verl-agent / VerlTool 计算编排最成熟，迁移成本低
    环境种类多、快速迭代算法 SkyRL 环境是一等公民，模块可换
    轨迹长尾严重、必须异步 AReaL 全异步 + 陈旧度控制是它的主线
    研究算法、先看清动力学 RAGEN 诊断工具齐全，环境受控
    已有 Agent 产品、局部加 RL Agent Lightning 不重写现有代码
    只做单轮推理 RL veRL / TRL / OpenRLHF 别为多轮复杂度买单

    选型时容易忽略的三件事¶

    • 掩码和旧对数概率是不是框架原生支持。 多轮训练的正确性全在轨迹管理上（1.1）。如果框架要你自己拼这两样，先做一个小规模对拍测试：同一条轨迹，训练端重算的对数概率和采样端记录的差多少。
    • 环境并发模型。 沙箱是进程、容器还是远程服务，复位要多久，决定了采样吞吐上限，和算法无关。
    • 异步的陈旧度有没有护栏。 支持异步不等于管得住旧数据。看它有没有版本过滤、ESS 监控（1.6）这类机制，没有就要自己加。

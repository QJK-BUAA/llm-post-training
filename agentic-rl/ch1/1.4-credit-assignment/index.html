    1.4 赢了到底算哪一步的功劳？跨步信用分配¶

    本节摘要

    整条轨迹共用一个优势，会把错误的第一步和立功的第三步一起奖了。本节讲四种拆法，按「要不要多花采样」排开：VinePPO 在中间点重采续写来估值；GiGPO 免费利用多条轨迹途经的相同状态；ProxMO 把「相同」放宽成「语义相近」；ELPO 用二分法定位第一个不可挽回的错误步。每种都配退货或购物例子手算。

    先把问题说成一句人话¶

    两条路都走到了同一个路口，往左的赢了、往右的输了。不用请裁判，你也知道这个路口该往左。

    信用分配的所有方法，本质都是在制造或寻找这种「同一起点、不同走法、结局不同」的对照。区别只在于：起点是真实重合的，还是采样造出来的，还是语义上近似的。

    方法一：VinePPO——在中间点重采，问「从这里出发能赢几次」¶

    一句话直觉：走到半路停下来，从这里独立重走很多次，看胜率。胜率比上一步高，说明这一步走得好。

    VinePPO（arXiv:2410.01679）本来是给单轮推理做无价值网络的步级估计：把一条轨迹在中间前缀处截断，从那里采样 \(K\) 条续写，用平均回报当这个状态的价值 \(V(s)\)，相邻两步价值之差就是这一步的功劳。它不需要训练 Critic，估计在给定策略下是蒙特卡洛无偏的。

    代价是采样。每个想估值的中间点都要重走 \(K\) 次。纯文本推理里重放前缀很便宜；真实工具环境里，走到中间状态可能已经调了五次不可逆的接口（比如已经下单），重走不一定可行。这是它迁到 Agent 时的最大限制。

    方法二：GiGPO——同一个路口，免费分组¶

    一句话直觉：多条轨迹自然会经过相同的中间状态。把在同一状态下做不同动作的步拎出来比一比后续结局，功劳就分出来了，一次额外采样都不用花。

    GiGPO（Group-in-Group Policy Optimization，arXiv:2505.10978，南洋理工大学与 Skywork AI）有两层优势：

    \[ \hat A_{i,t} = \underbrace{A^{\text{ep}}_i}_{\text{整条轨迹比同组平均好多少}} \;+\; \omega\cdot \underbrace{A^{\text{step}}_{i,t}}_{\text{在同一个状态下，这个动作比同状态的其他动作好多少}} \]

    第二层靠一张哈希表：把每条轨迹每一步的环境状态做键，相同键的步归成一组，比较它们各自从这一步往后的折扣回报。实现上不需要额外 rollout，论文称之为 anchor state grouping。

    3 步手算：局部是正的，全局是负的¶

    同一个退货请求采了 3 条轨迹。第 2 步结束时，三条都到了同一个状态：订单页已打开、政策未查（锚点状态 \(s\)）。接下来动作不同：

    轨迹 在 \(s\) 的动作 从 \(s\) 往后的折扣回报 \(R\) 整轨终局
    甲 直接查政策 0.9 后来结论写错，整轨 -0.2
    乙 又查了一遍订单 0.2 勉强答对，整轨 +0.4
    丙 直接查政策 0.9 答对，整轨 +0.8

    锚点组内平均回报是 \((0.9+0.2+0.9)/3\approx0.67\)。步级优势：甲 \(0.9-0.67=+0.23\)，乙 \(-0.47\)，丙 \(+0.23\)。

    注意甲：整轨是负的（\(A^{\text{ep}}<0\)），但在路口这一步它做对了（\(A^{\text{step}}>0\)）。整轨平摊会把甲的正确查询一起罚掉；GiGPO 让这一步至少得到正向信号。反过来，乙整轨赢了，但它在路口浪费了一步，步级信号是负的——这正是我们想要的区分。

    边界：看起来一样，不一定真的是一回事¶

    • 哈希键要求状态能可靠地变成同一个键。结构化环境（购物车页、文件路径、报错码）容易；自由文本观测里混着时间戳、随机 ID，就要先规范化。
    • 观测相同不等于状态相同。 两条轨迹都显示「订单已发货」，但一条的用户其实已申请拦截，历史不同，后续最优动作就不同。用表面观测分组，分出来的是相关性，不是因果。GiGPO 的组内回报差不能直接读成「这个动作导致了成功」。
    • 分组里包含轨迹自己时，基线和自己的回报相关，会带来一点偏差；样本越少越明显。严谨实现会考虑留一法（leave-one-out），或至少知道有这个偏差在。

    方法三：ProxMO——不是同一个路口，意思相近也算¶

    一句话直觉：GiGPO 要求两个状态一字不差。在文本世界里太苛刻。改成按语义相似度加权：越像的状态，对基线的发言权越大。

    ProxMO（Proximity-Based Multi-Turn Optimization，arXiv:2602.19225）的步级基线是同任务组内其他步回报的加权平均，权重来自 TF-IDF 余弦相似度过一个温度 softmax：

    \[ B_{i,t}=\sum_j w_{ij}R_j,\qquad w_{ij}=\frac{\exp(\text{sim}(s_{i,t},s_j)/\tau_s)}{\sum_m \exp(\text{sim}(s_{i,t},s_m)/\tau_s)},\qquad A^{\text{step}}_{i,t}=R_i-B_{i,t} \]

    它不需要另训一个向量模型，TF-IDF 就够用，这也是它工程上轻的原因。另一半设计是按组成功率调节整轨优势的强度（难题的信号放大，易题的信号收敛）。

    边界和 GiGPO 同源，而且更软：相似度高不保证可比；权重里包含自己时同样有自包含偏差；温度 \(\tau_s\) 太小退化成 GiGPO 的硬分组，太大则把不相干的状态也平均进来。ProxMO 的候选集合限制在同一任务的组内，不是全局乱比。

    方法四：ELPO——二分查找第一个不可挽回的错误步¶

    一句话直觉：像用 git bisect 查哪次提交改坏了代码。20 步失败了，退回第 10 步重跑几次：能救回来，病根在后半段；救不回来，前半段就已经歪了。

    ELPO（arXiv:2602.09598）把这个想法做成算法：在失败轨迹上取中点，固定前缀、重采后缀，看还能不能成功，以此二分定位 first irrecoverable step。定位之后再分层给优势：错误步之前给接近中性的信号，错误步本身给强负信号，并放宽这一步的负侧裁剪，让纠正的步子能迈得更大。

    代价是探测采样。\(O(\log T)\) 说的是探测点个数，每个点都要采若干条后缀，总成本是点数乘每点采样数。还有一个前提：错误得是「一步错、步步错」型。像搜索任务那种每轮相对独立、早期查错后面还能补的轨迹，不可挽回点可能根本不存在，硬套会误判。

    四种拆法怎么选¶

    方法 额外采样 需要什么 适合
    VinePPO 多，每个估值点 \(K\) 条 能廉价重放前缀 纯文本推理、状态可复现的环境
    GiGPO 无 状态能做可靠的键 网页、购物车、文件系统等结构化状态
    ProxMO 无 文本相似度可信 自由文本观测、状态难以精确匹配
    ELPO 中，\(O(\log T)\) 个探测点 错误有明确转折点、后缀可重采 代码排障、长推理链定位

    共同的未解问题是：这些方法分出来的都是统计对照，不是因果证明。状态可比性越差，归因越只能当启发式信号用。下一步是探索——就算归因再准，组里一条正例都没有时，还是没有东西可分。下一节讲怎么先采出正例。
